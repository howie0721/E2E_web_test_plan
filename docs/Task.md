# 專案基礎要求

1. 測試網址：https://www.dogcatstar.com/
2. **白箱測試**
    1. 設計：滿足「會員登入」且「商品加入購物車」可能的 E2E Test Case
        - 說明 Test Case 設計脈絡
    2. **實作 E2E：會員登入 & 商品加入購物車**
        - 以 **Playwright**（或你擅長的工具）實作。
        - 使用 **storageState**（或等價機制）將「登入狀態」儲存為可重用 **Auth**。
        - 至少覆蓋：
            - 登入成功
            - 從商品頁加入購物車
        - 使用 **storageState**（或其他相似機制）將「登入狀態」儲存為可重用 **Auth**。
        - 說明等待策略
        - 需產出測試結果報告
        - 注意：請勿執行下單
    3. 設計：API 自動化測試
        - 列出關鍵 API
        - 分析 API 呼叫方式並規劃 API 測試方法
        - 不實作，僅提供分析結果並完成規劃即可
3. **專案架構說明**
    - 需要分層與可重用：`/pages`（POM/Screenplay）、`/fixtures`（Auth/測資）、`/helpers`（API/資料工廠/等待）、`/tests`（以功能域分組）。
    - `README` 說明設計理由與未來如何擴充。

# 加分題（可選其中幾項）

1. 黑箱測試
    - 分析潛在的錯誤或可能的系統漏洞
    - 邊界值測試規劃
2. 購物車增加選擇優惠券的變因時會怎麼規劃測試案例
    - 規劃架構以及描述思考脈絡即可
3. E2E
    - 把可能不適合 E2E 的 API 盤點出來
    - 使用 Network stubbing / route or HAR/mock 調整 E2E Testing 使其更穩定
4. 作業透過 AI 協作增進效率，並描述做法
