# Shepherdtech 購物車自動化測試企劃書

## 1. 測試目標與範圍
- 驗證購物車核心功能：商品加入、重複加入、移除、持久化
- 覆蓋登入/未登入、規格選取、異常處理、資料同步
- 保障用戶操作流程正確、資料不遺失
- 實際執行環境：Windows 10/11、Chrome/Edge 最新版、Node.js 18.x、Playwright 1.x
- 測試資料初始化：storageState.json、mock API（如有）
- 例外/異常情境：網路斷線、API timeout、庫存不足、規格未選、UI 元素異常
- 擴充性與維護：商品/規格可快速擴充，selector 變動易調整，失敗自動截圖與 log 收集
- 團隊協作：case 命名規則、PR review、CI/CD 觸發條件
- 報告與追蹤：自動產出測試報告、失敗追蹤、覆蓋率指標
- 用戶體驗保障：針對 UX 關鍵流程設計專屬 test case，驗證提示訊息與異常回饋

## 2. 架構設計
- Playwright 元件化：所有操作（加入、移除、驗證）皆封裝 helper，易維護、可重用
- 測試資料驅動：商品 index、規格、數量皆可參數化
- 測試流程分層：前置清空、操作、驗證、異常流程獨立

## 3. 主要測試案例
- 單商品加入：驗證加入後件數正確
- 多商品加入：for 迴圈加入多商品，驗證件數
- 重複加入：同商品多次加入，驗證 input value
- 移除商品：加入後移除，驗證購物車為空或剩餘件數
- 持久化：加入商品後重新整理/登出再登入，驗證資料不遺失
- 異常流程：網路錯誤、規格未選、庫存不足

## 4. 驗證方法
- UI 層斷言：input value、商品列表、提示訊息
- 資料層斷言：localStorage/sessionStorage（如有）
- session/狀態切換：storageState 驗證

## 5. 自動化流程
- CI/CD 整合：npx playwright test 全自動執行
- 測試報告：playwright-report/，可視覺化結果
- 維護策略：selector 集中管理、helper 元件化

## 6. 風險與覆蓋率分析
- 覆蓋所有核心操作路徑
- 針對異常/邊界情境設計額外 test case
- 定期回歸測試，保障新功能不破壞既有流程

## 7. Demo 流程說明
- 先介紹測試目標與架構設計
- 逐步展示主要 test case（加入、移除、持久化）
- 強調元件化、資料驅動、驗證邏輯精確
- 展示自動化報告與 CI/CD 整合
- 最後說明覆蓋率與風險控管
