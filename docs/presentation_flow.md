# Shepherdtech Playwright 測試企劃報告流程

1. 開場：簡述測試目標與專案背景
   - 大家好，今天我要分享汪喵星球電商網站的自動化測試企劃。本企劃聚焦於會員登入與購物車功能，目標是確保所有主要操作都能穩定運作，並驗證用戶資料在各種操作下都能持久保存。前端測試能有效驗證資料持久性與操作安全，後端資料安全則需搭配資安設計共同保障。希望藉由完善的自動化測試，讓每位使用者都能享有流暢、可靠的購物體驗。

2. 架構設計亮點
   - 首先，所有重複操作都元件化，封裝成 helper function，讓程式碼更易維護、可重用，團隊協作時也能快速上手。
   資料夾分層非常明確，像是測試、helpers、fixtures、pages 都有獨立結構，方便管理與日後擴充，讓專案規模變大時也不會混亂。
    mock server，可以模擬 API 回應和異常情境，這讓測試覆蓋率大幅提升，不論是正常流程還是邊界、異常狀況都能驗證到。
    此外，CI/CD 已經整合，搭配團隊協作規範，確保每次提交都能自動測試、產出報告，品質一致、流程自動化。
    最後，像多環境參數、異常攔截、覆蓋率工具等細節也都規劃進來，讓整個架構更完整、可擴充，能因應未來不同需求或規模成長。



3. 主要測試案例逐一說明
   - 在主要測試案例部分，我們針對購物車的各種核心操作都設計了自動化驗證：
   - 首先是單商品加入，確保用戶能順利將商品加入購物車。
   - 多商品加入，驗證同時加入多個商品時，購物車內容與數量都正確。
   - 重複加入，測試同一商品多次加入時，數量是否正確累加。
   - 移除商品，確認用戶能正確刪除購物車內的商品。
   - 持久化驗證，確保購物車內容在頁面重整、切換裝置或 session 切換後依然正確保存。
   - 最後是異常流程，例如網路錯誤、商品規格未選等，驗證系統能正確提示用戶，避免異常操作造成體驗不佳。
   這些案例能全面覆蓋購物車的主要功能與邊界情境，確保用戶在各種狀況下都能有穩定、可靠的操作體驗。



4. 驗證方法
   - 在驗證方法上，我們會從三個層面來確保功能正確：
      - 首先是 UI 層斷言，像是檢查 input 欄位的值、提示訊息是否正確顯示，確保用戶操作時畫面反饋都沒問題。

      - 再來是資料層斷言，會直接驗證 localStorage 或 sessionStorage 的內容，確認資料有正確寫入、同步，避免只驗畫面卻漏掉資料異常。

      - 最後是 session 切換驗證，利用 Playwright 的 storageState 功能，模擬不同 session 或裝置切換，確保用戶資料能正確保存與還原。
   - 這三種驗證方式能全方位保障功能正確性與資料一致性。

5. 自動化與維護策略
   - 在自動化與維護策略方面，我們已經將 CI/CD 流程整合進來，所有測試都能自動執行並產出報告，讓每次程式碼更新都能即時驗證品質，減少人為疏漏。
   - selector 也有集中管理，避免重複、難維護的選擇器散落在各處，讓測試腳本更穩定、日後維護也更方便。
   - 另外，所有重複操作都元件化成 helper function，不僅提升程式碼可讀性，也讓團隊協作時能快速複用、降低重工。
   - 這些策略讓我們的自動化測試不只可靠，也能隨著專案成長輕鬆維護與擴充。

6. 風險控管與覆蓋率
   - 在風險控管與覆蓋率方面，我們確保所有核心操作路徑都被完整覆蓋，避免有遺漏的功能沒被驗證到。
   - 同時也特別設計了各種邊界與異常情境的測試，像是輸入錯誤、網路異常、資料異常等，確保系統在各種狀況下都能正確反應。
   - 此外，我們會定期執行回歸測試，確保每次功能調整或新功能上線後，舊有功能都能維持穩定，降低潛在風險。
   - 這樣的設計能大幅提升產品品質與可靠性，讓團隊對每次上線都更有信心。
