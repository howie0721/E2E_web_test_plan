## 1. 潛在錯誤與系統漏洞分析

### 1.1 輸入驗證不足
- **風險說明**：手機號碼、Email、密碼、OTP 格式未嚴格檢查，可能導致異常或安全漏洞。
- **可能影響**：
  - SQL Injection（若後端未防護）
  - 儲存格式異常資料
  - 繞過驗證邏輯
- **測試建議**：
  - 測試空值、特殊字元（`<script>`、`' OR 1=1 --`）
  - 超長字串（1000+ 字元）
  - Unicode、Emoji、全形/半形混用

### 1.2 權限控管不嚴
- **風險說明**：未登入可操作會員專區、購物車、結帳等功能。
- **可能影響**：
  - 未授權存取敏感資料
  - 繞過付費機制
  - 資料外洩
- **測試建議**：
  - 清除 cookies/storage 後直接訪問會員頁面
  - 修改 localStorage/sessionStorage 模擬權限提升
  - API 請求移除或竄改 token

### 1.3 Session/Token 管理不當
- **風險說明**：登出後仍可操作敏感功能，或 storageState/cookie 遺失未自動登出。
- **可能影響**：
  - Session Fixation
  - Token 重播攻擊
  - 多裝置登入衝突
- **測試建議**：
  - 登出後重複使用舊 token
  - Token 過期時間驗證
  - 同帳號多裝置/多分頁登入測試

### 1.4 錯誤訊息洩漏
- **風險說明**：API 或前端回傳過多系統細節，易被惡意利用。
- **可能影響**：
  - 洩漏資料庫結構
  - 洩漏系統版本與技術棧
  - 幫助攻擊者構造攻擊
- **測試建議**：
  - 故意觸發 400、401、404、500 錯誤
  - 觀察錯誤訊息是否包含敏感資訊（SQL、路徑、版本號）

### 1.5 跨站請求偽造（CSRF）/跨站腳本（XSS）
- **風險說明**：表單、輸入框、購物車等未做防護。
- **可能影響**：
  - 惡意腳本注入
  - 偽造用戶操作
  - Cookie 劫持
- **測試建議**：
  - 輸入 `<script>alert('XSS')</script>` 等測試字串
  - 檢查 CSP (Content Security Policy) 設定
  - 驗證 CSRF Token 存在與有效性

### 1.6 資料一致性問題
- **風險說明**：多裝置/多分頁同時操作購物車，資料不同步。
- **可能影響**：
  - 購物車數量異常
  - 結帳金額錯誤
  - 庫存超賣
- **測試建議**：
  - 雙開瀏覽器同時加入/移除購物車商品
  - API 並發請求測試
  - WebSocket/Polling 同步機制驗證

### 1.7 伺服器/網路異常處理不足
- **風險說明**：API timeout、網路斷線時未妥善提示或重試。
- **可能影響**：
  - 用戶操作迷失
  - 資料遺失
  - 重複提交
- **測試建議**：
  - 模擬網路中斷（Chrome DevTools > Network > Offline）
  - API 延遲測試（Throttling）
  - 伺服器 503/504 錯誤處理

### 1.8 交易流程未防止重複提交
- **風險說明**：連點「加入購物車」或「送出訂單」造成重複資料。
- **可能影響**：
  - 訂單重複
  - 金額重複扣款
  - 庫存計算錯誤
- **測試建議**：
  - 快速連點按鈕
  - 檢查前端 debounce/throttle 機制
  - 後端冪等性驗證（Idempotency Key）

## 2. 邊界值測試規劃

### 2.1 手機號碼格式測試

| 測試項目 | 測試值 | 預期結果 |
|---------|--------|---------|
| 正常格式 | `0912345678` | 通過 |
| 國碼格式 | `+886912345678` | 通過或格式化 |
| 最短長度 | `091234567`（9位） | 拒絕 |
| 最長長度 | `09123456789`（11位） | 拒絕 |
| 空值 | `` | 拒絕，提示必填 |
| 特殊字元 | `0912-345-678` | 拒絕或自動過濾 |
| 字母 | `091234567A` | 拒絕 |
| 全形數字 | `０９１２３４５６７８` | 拒絕或轉半形 |

### 2.2 Email 格式測試

| 測試項目 | 測試值 | 預期結果 |
|---------|--------|---------|
| 正常格式 | `test@example.com` | 通過 |
| 無 @ 符號 | `testexample.com` | 拒絕 |
| 多個 @ | `test@@example.com` | 拒絕 |
| 空值 | `` | 拒絕，提示必填 |
| 超長 Email | `a`*200+`@example.com` | 拒絕或截斷 |
| 特殊字元 | `test+tag@example.com` | 通過（RFC 允許） |
| Unicode | `測試@example.com` | 依規格決定 |

### 2.3 OTP 驗證測試

| 測試項目 | 測試值 | 預期結果 |
|---------|--------|---------|
| 正確 OTP | `123456` | 通過 |
| 錯誤 OTP | `000000` | 拒絕，提示錯誤 |
| 過期 OTP | 5 分鐘前的 OTP | 拒絕，提示過期 |
| 空值 | `` | 拒絕，提示必填 |
| 不足位數 | `12345`（5位） | 拒絕 |
| 超過位數 | `1234567`（7位） | 拒絕或截斷 |
| 連續錯誤 | 連續 5 次錯誤 | 鎖定或要求重發 |
| 特殊字元 | `12-34-56` | 拒絕 |

### 2.4 商品數量/購物車上限測試

| 測試項目 | 測試值 | 預期結果 |
|---------|--------|---------|
| 正常數量 | `1`, `5`, `10` | 通過 |
| 0 | `0` | 拒絕或移除商品 |
| 負數 | `-1` | 拒絕 |
| 超過庫存 | `9999` | 拒絕或限制最大值 |
| 非數字 | `abc` | 拒絕 |
| 小數 | `1.5` | 拒絕或四捨五入 |
| 購物車上限 | 100 項商品 | 提示上限 |

### 2.5 優惠券代碼測試

| 測試項目 | 測試值 | 預期結果 |
|---------|--------|---------|
| 有效優惠券 | `SAVE100` | 通過，折扣生效 |
| 無效優惠券 | `INVALID` | 拒絕，提示無效 |
| 過期優惠券 | `EXPIRED2024` | 拒絕，提示過期 |
| 空值 | `` | 拒絕，提示必填 |
| 超長代碼 | 100 字元 | 拒絕或截斷 |
| 重複使用 | 已使用過的優惠券 | 拒絕，提示已使用 |
| 大小寫混用 | `save100`, `SAVE100` | 依規格決定 |

### 2.6 Session/Token 測試

| 測試項目 | 測試值 | 預期結果 |
|---------|--------|---------|
| 有效 Token | 正常登入後的 token | 通過 |
| 過期 Token | 1 小時前的 token | 401，要求重新登入 |
| 損毀 Token | 修改部分字元 | 401，拒絕存取 |
| 空 Token | 移除 token | 401，跳轉登入頁 |
| 同帳號多裝置 | 2 個裝置同時登入 | 依規格決定（允許或踢出） |

### 2.7 API 輸入參數測試

| 測試項目 | 測試值 | 預期結果 |
|---------|--------|---------|
| 正常參數 | 完整且正確的 payload | 200 OK |
| 缺少必填欄位 | 移除 `billing_country` | 400/422，提示缺欄位 |
| 異常型別 | `quantity: "abc"` | 400/422，提示型別錯誤 |
| 極大值 | `quantity: 999999` | 400/422 或限制最大值 |
| 極小值 | `quantity: -1` | 400/422，拒絕負數 |
| null 值 | `billing_country: null` | 400/422，拒絕 null |

### 2.8 UI 操作測試

| 測試項目 | 測試方式 | 預期結果 |
|---------|---------|---------|
| 快速連點 | 0.1 秒內點擊 10 次 | 不重複提交 |
| 切換分頁 | 開 2 個分頁同時操作 | 資料同步 |
| 斷線重連 | 斷網後重新連線 | 自動重試或提示 |
| 瀏覽器回上一頁 | 結帳後按返回 | 不重複扣款 |
| 重新整理 | F5 重新整理 | 狀態保持或提示 |

## 3. 測試案例設計

### 3.1 登入功能黑箱測試

#### TC-BLACKBOX-LOGIN-001: 手機號碼邊界值測試
- **前置條件**：開啟登入頁面
- **測試步驟**：
  1. 輸入 9 位數手機（`091234567`）
  2. 點擊「發送驗證碼」
- **預期結果**：提示「手機號碼格式錯誤」

#### TC-BLACKBOX-LOGIN-002: OTP 過期測試
- **前置條件**：已發送 OTP
- **測試步驟**：
  1. 等待 5 分鐘
  2. 輸入正確的 OTP
  3. 點擊「登入」
- **預期結果**：提示「驗證碼已過期」

#### TC-BLACKBOX-LOGIN-003: 連續錯誤 OTP 測試
- **前置條件**：已發送 OTP
- **測試步驟**：
  1. 連續輸入 5 次錯誤 OTP
- **預期結果**：帳號鎖定或要求重發 OTP

### 3.2 購物車功能黑箱測試

#### TC-BLACKBOX-CART-001: 商品數量邊界值測試
- **前置條件**：商品詳情頁
- **測試步驟**：
  1. 輸入數量 `0`
  2. 點擊「加入購物車」
- **預期結果**：提示「數量不可為 0」

#### TC-BLACKBOX-CART-002: 購物車上限測試
- **前置條件**：已登入
- **測試步驟**：
  1. 加入 100 項商品（假設上限 100）
  2. 嘗試加入第 101 項
- **預期結果**：提示「購物車已滿」

#### TC-BLACKBOX-CART-003: 多分頁同步測試
- **前置條件**：已登入，開啟 2 個分頁
- **測試步驟**：
  1. 分頁 A 加入商品 X
  2. 切換到分頁 B，檢查購物車
- **預期結果**：分頁 B 自動顯示商品 X

### 3.3 結帳功能黑箱測試

#### TC-BLACKBOX-CHECKOUT-001: 優惠券邊界值測試
- **前置條件**：購物車有商品
- **測試步驟**：
  1. 輸入 100 字元的優惠券代碼
  2. 點擊「套用」
- **預期結果**：提示「優惠券代碼過長」

#### TC-BLACKBOX-CHECKOUT-002: 重複提交訂單測試
- **前置條件**：結帳頁面
- **測試步驟**：
  1. 快速連點「送出訂單」5 次
- **預期結果**：只產生 1 筆訂單

### 3.4 權限與安全測試

#### TC-BLACKBOX-AUTH-001: 未登入存取會員頁
- **測試步驟**：
  1. 清除 cookies/storage
  2. 直接訪問 `/my-account`
- **預期結果**：跳轉至登入頁

#### TC-BLACKBOX-AUTH-002: Token 竄改測試
- **測試步驟**：
  1. 登入後，修改 localStorage 的 token
  2. 呼叫購物車 API
- **預期結果**：回傳 401 Unauthorized

#### TC-BLACKBOX-AUTH-003: XSS 注入測試
- **測試步驟**：
  1. 在商品評論輸入 `<script>alert('XSS')</script>`
  2. 送出評論
  3. 重新載入頁面
- **預期結果**：腳本被轉義，不執行

### 3.5 網路異常測試

#### TC-BLACKBOX-NETWORK-001: API Timeout 測試
- **測試步驟**：
  1. 開啟 Chrome DevTools > Network > Slow 3G
  2. 加入商品到購物車
- **預期結果**：顯示載入中，或提示「網路不穩，請稍後再試」

#### TC-BLACKBOX-NETWORK-002: 斷線重連測試
- **測試步驟**：
  1. 加入商品到購物車
  2. 中途斷網 10 秒
  3. 重新連線
- **預期結果**：自動重試或提示重新整理

## 4. 測試優先級與建議

### 4.1 高優先級（P0）
- ✅ 登入/登出功能
- ✅ 購物車加入/移除商品
- ✅ 結帳流程（金額計算、訂單產生）
- ✅ 權限驗證（未登入、Token 過期）
- ✅ 重複提交防護

### 4.2 中優先級（P1）
- ⚠️ 邊界值測試（手機、Email、OTP、數量）
- ⚠️ 多裝置/多分頁同步
- ⚠️ 網路異常處理
- ⚠️ 錯誤訊息洩漏檢查

### 4.3 低優先級（P2）
- 🔄 UI/UX 細節（按鈕狀態、提示文字）
- 🔄 效能測試（並發、大量資料）
- 🔄 瀏覽器相容性測試

### 4.4 實作建議

1. **自動化優先**：高優先級測試案例應優先自動化，減少回歸測試時間。
2. **參數化測試**：邊界值測試可用 Playwright 的 `test.describe.parallel` + data-driven 方式實作。
3. **Mock/Stub**：網路異常、API timeout 測試可用 Playwright 的 `route` 功能模擬。
4. **安全測試工具**：XSS、CSRF 測試可搭配 OWASP ZAP 或 Burp Suite。
5. **持續監控**：整合 CI/CD，每次部署前執行黑箱測試，確保品質。
